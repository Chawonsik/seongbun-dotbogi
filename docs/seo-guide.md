# SEO 학습 정리 (새싹 SEO 1~3 요약)

원자료: 새싹 SEO 강의 노션 3편 (2026-09-29 확인). 원문 전재가 아니라 우리 랜딩에 적용하려고 뽑은 요약이다.
원문 2편에는 강사 계정의 API 키가 노출돼 있다. 옮기지 않았고 쓰지 않는다.

## 1편. 테크니컬 SEO: 읽히는 조건

### 배포 전 점검표 20개

| 묶음 | 항목 |
|---|---|
| 주소 구조 | URL 소문자와 하이픈, 깊이 3단계 이내 |
| | 대표 주소 하나로 통일 (www 유무, http/https) |
| | 홈에서 3번 클릭 안에 모든 페이지 도달 |
| | 고아 페이지(어디서도 링크 안 된 페이지) 없음 |
| 크롤링 | /robots.txt 가 루트에서 열림 |
| | 실수로 전체 차단(Disallow: /) 하지 않음 |
| | /sitemap.xml 의 주소가 전부 200 |
| 페이지 정보 | 페이지마다 다른 title |
| | 페이지마다 다른 meta description |
| | canonical 이 자기 자신을 가리킴 |
| | og:image 는 절대 주소 |
| | 검색에 안 나와야 할 페이지에 noindex |
| 브랜드 신호 | /favicon.ico 가 열림 (정사각형, 48px 이상 권장) |
| | 홈에만 WebSite 구조화 데이터 (name, url 필수) |
| 읽히는 조건 | 홈에 Organization 구조화 데이터 |
| | view-source 에 본문 글자가 보임 (JS로만 그리면 로봇에게 빈 페이지) |
| 속도 | LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하 (FID는 폐지) |
| | 이미지에 width/height 지정 |
| 확인 | 서치콘솔 페이지 보고서 오류 없음 |
| | 리치 결과 테스트 오류 없음 |

### 알아둘 사실
- 검색 결과 한 칸의 출처: 제목은 title, 설명은 meta description, 아이콘은 link rel="icon", 사이트 이름은 WebSite JSON-LD. 없으면 도메인이 뜬다.
- 구글은 title이 본문과 안 맞으면 다시 쓴다. title, h1, 첫 문단을 맞춘다.
- 제목 60자, 설명 160자는 공식 기준이 아니라 관행이다. 한글은 빨리 잘리니 핵심어를 앞에 둔다.
- 소규모 사이트 구조화 데이터는 WebSite, Organization, (깊을 때만) BreadcrumbList 세 개면 충분하다.
- FAQ 리치결과는 폐지됐다(2023-08 제한, 2026-05 완전 제거). 그래도 본문 FAQ는 AI 답변 인용용으로 쓴다.
- 리치 결과 테스트에서 WebSite, Organization은 "감지된 항목 없음"이 정상이다. 문법은 스키마 검증기로 본다.
- PageSpeed는 실사용자 데이터가 구글 기준이다. 방문자가 적으면 안 나온다.
- 페이지가 1개여도 할 것: 주소 구조, title과 description, 파비콘, WebSite 구조화 데이터.

## 2편. 검색 시장과 키워드

- 산출물은 키워드 시트 30~50줄: 검색 시장 / 키워드 / 검색량 / 의도 / 여정 단계 / 관련 질문.
- 검색 시장을 3~5개로 먼저 나눈다 (문제, 방법, 가격 비교, 업체 선택, 브랜드 확인 식). 시장마다 필요한 페이지가 다르다.
- 검색량: 네이버 검색광고 키워드도구가 주력이다. 개인 가입, 결제 수단 불필요, 월간 PC와 모바일 검색수가 숫자로 나온다. 구글 키워드 플래너는 광고 집행 전에는 범위로만 나와서 발굴용으로만 쓴다.
- 검색량은 절대값이 아니라 상대 순위로 본다.
- 무료로 얻는 것: 구글 자동완성, 관련 질문(PAA, 펼칠수록 늘어남), 관련 검색어(여정의 다음 칸).
- 의도 3가지: 이해(설명 글), 비교(표와 후기), 결정(가격과 버튼).
- 여정 맵 네 칸에 나눠 담으면 보통 마지막 단계만 차 있다. 빈 칸이 다음에 만들 페이지다.
- 신생 사이트는 롱테일(구체적, 검색량 작음)이 현실적이다.

## 3편. 온사이트 실행

- 같은 답을 원하는 키워드는 한 페이지로 묶는다. 판단법: 두 키워드의 구글 1페이지가 비슷하면 같은 페이지.
- 우선순위: P0 이미 있는 페이지의 제목과 설명만 고치기(오늘), P1 새 글 한 편(이번 달), P2 미루기.
- 배치 규칙: 대표 키워드는 title과 h1, 묶인 키워드는 본문, 관련 질문은 h2나 FAQ 한 줄, 의도는 페이지 요소(설명, 표, 버튼).
- 제목 공식: 대표 키워드 + 구체적인 약속 | 브랜드명. 브랜드명을 앞에 두지 않는다.
- 관련 질문은 말을 바꾸지 않고 그대로 소제목으로 쓴다. 답은 첫 문장에 결론, 굵게.
- 키워드마다 AI에게 묻는 문장형 질문을 하나씩 만든다. ChatGPT와 구글 AI 개요에 넣어 10개 중 몇 개에서 인용되는지 세면 기준선이 된다.
- 배포 후 서치콘솔 URL 검사에서 색인 생성 요청. 2주 뒤 재확인, 한 달 뒤 실적 검색어 확인, 예상 못 한 검색어를 시트에 추가.
- 키워드는 제목에 한 번, h1에 한 번, 본문에 자연스럽게. 반복은 손해다.

## 성분돋보기 랜딩 현황 (2026-09-29 실측)

| 항목 | 상태 |
|---|---|
| /robots.txt | 404, 없음 |
| /sitemap.xml | 404, 없음 |
| /favicon.ico | 404. 인라인 SVG 아이콘만 있음 |
| title | "성분돋보기". 검색어 없이 브랜드명만 있음 |
| meta description | 있음 |
| canonical | 없음 |
| og:image | 없음 |
| 구조화 데이터 | 없음 |
| h1 | "이름값은 몇 번째?". title과 다른 이야기 |
| 처리방침 noindex | 있음 |
| 서치콘솔, 네이버 서치어드바이저 등록 | 안 함 |

키워드 시트와 제목 문구는 PDRN 실험 구조와 광고 문구가 정해진 뒤에 만든다. 기술 항목(robots, sitemap, favicon, canonical, og:image, WebSite JSON-LD)은 그 전에 해도 된다.
