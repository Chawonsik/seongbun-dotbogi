## 1. 로그 설계 (Amplitude 이벤트 목록)

### 원칙
- 이벤트 이름은 지금 GA4 이름을 그대로 쓴다. 워밍업 기록과 비교하기 쉽고 코드 변경이 가장 작다.
- 모든 이벤트에 UTM 네 값을 이벤트 속성으로 붙인다. Amplitude의 자동 유입 속성은 첫 방문 기준이라 두 번째 방문부터 섞일 수 있어서 이벤트마다 직접 붙인다.
- 개인정보는 보내지 않는다. 검색어 원문, 붙여넣은 전성분 텍스트, 자유 입력 답변은 보내지 않는다.
- 로그인이 없으므로 사용자는 Amplitude 기기 ID로만 구분한다.

### 공통 속성 (모든 이벤트)

| 속성 | 예시 | 출처 |
|---|---|---|
| utm_source | facebook | 링크 |
| utm_medium | cpc | 링크 |
| utm_campaign | kr_2040_skincare | 링크 |
| utm_content | s1_name | 링크 |
| stage | s1 | utm_content 앞부분에서 계산 |
| arm | name | utm_content 뒷부분에서 계산 |

UTM이 없는 방문(직접 접속, 검색, 공유)은 값을 `(none)`으로 보내 광고 유입과 구분한다.

### 이벤트

| 이벤트 | 언제 | 추가 속성 | 지금 상태 | 분석에서 쓰는 곳 |
|---|---|---|---|---|
| landing_view | 페이지가 열릴 때 1회 | 없음 | 새로 (GA4는 자동 수집이었음) | 소재별 방문 수, 클릭 대비 실제 도착 비율 |
| chip_click | 성분 칩을 누를 때 | ingredient | 있음 | PDRN 한 개라 비중 낮음. 유지만 |
| product_select | 검색 목록에서 제품을 고를 때 | product, ingredient | 있음 (found=1) | 소재별 제품 선택률 |
| search_miss | 두 글자 이상 쳤는데 결과가 없을 때 1회 | 없음 | 있음 (지금은 product_select found=0) | 데이터에 없는 제품을 찾는 비율. 이름을 분리해 선택률 계산을 깔끔하게 함 |
| paste_run | 전성분 붙여넣기 실행 | n (성분 수), found | 있음 | 깊은 관여 행동 |
| engaged_60s | 화면이 보이는 상태로 60초 누적 | 없음 | 있음 | 소재별 체류 비율 |
| survey_view | 설문 카드가 화면에 뜰 때 | trigger (select 또는 timer) | 새로 | 설문 응답률의 분모 |
| survey_answer | 문항에 답할 때 | q (q1, q2), answer (선택지 코드) | 새로 | 정성 데이터 |
| survey_close | 답하지 않고 닫을 때 | 없음 | 새로 | 응답 거부 비율 |
| faq_open | 접힌 설명 4항목 중 하나를 처음 열 때 (항목별 1회) | item (common, price, review, method) | 새로 | 읽는 사람 신호. 60초 체류와 함께 관여도로 봄 |

결정 (2026-09-29): faq_open 넣음, search_miss를 product_select에서 떼어 냄. 이벤트는 총 10개.

### 메타 픽셀
- 그대로 둔다. PageView와 ProductSelect(제품을 찾은 경우만)만 보낸다.
- 픽셀은 광고 최적화용이고 분석은 Amplitude로 한다.

### 주요 지표 계산 (Amplitude에서 볼 것)

| 지표 | 계산 | 나누는 기준 |
|---|---|---|
| 제품 선택률 | product_select 한 기기 ÷ landing_view 기기 | arm, stage |
| 60초 체류율 | engaged_60s 기기 ÷ landing_view 기기 | arm, stage |
| 설문 응답률 | survey_answer(q1) 기기 ÷ survey_view 기기 | arm |
| 유입 이유 분포 | survey_answer(q1) answer별 비율 | arm |

클릭률과 클릭당 비용은 메타 광고 관리자 숫자를 쓴다. Amplitude는 도착한 뒤의 행동만 본다.

## 2. UTM 값 규칙

### 형식
- 전부 영어 소문자와 밑줄만 쓴다. 한글과 띄어쓰기는 쓰지 않는다. 링크가 깨지거나 같은 값이 둘로 갈라지는 것을 막기 위해서다.
- 한 번 쓴 값은 실험 중에 바꾸지 않는다.

| 파라미터 | 값 | 규칙 |
|---|---|---|
| utm_source | facebook | 고정 |
| utm_medium | cpc | 고정 |
| utm_campaign | kr_2040_skincare | 타겟 이름. 국가_연령_관심사 |
| utm_content | {단계}_{소재} | 아래 표 |

### utm_content 값

| 단계 | A (성분 이름 소재) | B (효능 소재) |
|---|---|---|
| 1차 (이미지) | s1_name | s1_benefit |
| 2차 (이미지+문구) | s2_name | s2_benefit |

### 완성 링크 예시
```
https://seongbun-dotbogi.vercel.app/?utm_source=facebook&utm_medium=cpc&utm_campaign=kr_2040_skincare&utm_content=s1_name
```

결정 (2026-09-29): 타겟은 하나(kr_2040_skincare), 소재 이름은 위 표 4개 그대로.

### 무료 SNS 유입용 값 (결정 2026-09-29)

| 채널 | utm_source | utm_medium | utm_campaign | utm_content |
|---|---|---|---|---|
| 스레드 | threads | social | organic | 글 번호 (t01, t02 ...) |
| 네이버 블로그 | naver_blog | social | organic | 글 번호 (b01, b02 ...) |

- utm_medium을 social로 두어 광고(cpc)와 한 번에 나눠 볼 수 있게 한다.
- 글 번호와 글 제목의 대응은 이 문서 아래에 표로 적어 둔다.
- 검색 결과(SEO)로 들어오는 방문에는 UTM을 붙일 수 없다. Amplitude의 유입 경로(referrer)로 구분하고 UTM 값은 (none)으로 남는다.

### 광고 링크는 손으로 넣는다
메타 동적 값({{ad.name}})은 쓰지 않는다. 광고 이름을 잘못 지으면 값이 틀어지고 소재가 4개뿐이라 손으로 넣어도 부담이 없다.

### 코드에서 바꿀 것
- 지금은 utm_content만 읽어 `frame`이라는 이름으로 붙인다. 네 값을 모두 읽고 stage와 arm을 계산해 붙이도록 바꾼다.

## 3. 설문 문항

### 목적
클릭과 행동 데이터는 "무엇을 했는지"만 보여준다. 설문은 "왜 눌렀는지"를 묻는다. 가설인 "성분이 제품을 고르는 데 중요하다"에 대해 소재별로 응답 분포가 다른지를 본다.

### 띄우는 방식 (제안)
- 화면을 가리는 팝업이 아니라 결과 카드 아래에 붙는 작은 카드로 띄운다. 이탈을 늘리지 않기 위해서다.
- 조건: 제품을 처음 골랐을 때, 또는 20초가 지났을 때 중 먼저 오는 쪽. 한 기기에 한 번만 띄운다.
- 닫기 버튼을 둔다. 두 문항 모두 선택형이고 자유 입력은 받지 않는다.

결정 (2026-09-29): 20초. 근거 데이터가 없는 절충값이라 1차 뒤 survey_view 대비 응답률을 보고 2차 전에 다시 본다. Q1 선택지 그대로, Q2 넣음.

### 문항 초안

**Q1. 광고를 누른 이유에 가장 가까운 것은?** (하나 선택)

| 코드 | 선택지 |
|---|---|
| ingredient | 광고에 나온 성분이나 원료가 궁금해서 |
| effect | 광고에 나온 피부 효과가 궁금해서 |
| image | 이미지가 눈에 띄어서 |
| other | 기타 또는 잘 모르겠음 |

- 앞의 세 선택지는 방문자마다 순서를 섞는다. 첫 번째 선택지가 더 많이 선택되는 쏠림을 줄이려는 것이다. other는 항상 마지막에 둔다.
- A는 성분 이름이 있는 소재(예: PDRN 연어크림), B는 성분 이름 없이 효능만 말하는 소재(예: 재생크림)다. 선택지에 "PDRN"을 직접 쓰지 않는 것은 B로 들어온 사람에게 성분 이름을 알려 주지 않기 위해서다. 성분 쪽을 보고 눌렀는지 효과 쪽을 보고 눌렀는지를 가른다.

**Q2. 평소 화장품을 고를 때 성분표를 확인하나요?** (하나 선택)

| 코드 | 선택지 |
|---|---|
| always | 거의 항상 확인한다 |
| sometimes | 가끔 확인한다 |
| rarely | 거의 확인하지 않는다 |

- 성분 관여도로 응답자를 나누는 용도다. 예를 들어 "성분표를 자주 보는 사람일수록 A 소재에서 ingredient를 더 많이 골랐다"처럼 볼 수 있다.

### 해석 규칙 (미리 정함)
- 응답자는 클릭한 사람 중 답한 사람뿐이라 관찰로만 쓴다. 인과로 쓰지 않는다.
- 소재당 응답이 30건 미만이면 비율을 쓰지 않고 건수만 적는다.
- Q1의 소재별 분포 차이는 "A 소재로 들어온 응답자 중 ingredient를 고른 비율이 N%, B 소재는 M%"처럼 대상, 숫자, 조건을 넣어 쓴다.

### 개인정보
- 선택지 코드만 보내므로 개인을 알아볼 정보는 없다.
- 처리방침에 "설문 응답(선택지)"을 수집 항목으로 추가한다. GA4 삭제와 Amplitude 추가도 함께 고친다.
