# 계측 설계 초안: 로그, UTM, 설문

작성 2026-09-29 · 상태: 원식 결정과 파트너 검토 반영(2026-09-29). 랜딩은 가상 제품형으로 확정, 랜딩 디자인은 미정 · 기준: 재철 강사님 피드백 (PDRN 하나, A/B 두 소재, 1차 이미지만 다르게 7일, 2차 고른 이미지 하나에 문구만 다르게 7일)

2026-09-30 Amplitude 연결 전에 "무엇을 보낼지"를 정하려고 쓴 문서입니다.

기준 문서는 노션 결정 로그의 하위 페이지 "계측 설계 초안: 로그, UTM, 설문"입니다. 검토와 수정은 노션에서 하고 이 파일은 노션에 맞춰 옮깁니다. 마지막 동기화: 2026-10-02.

## 1. 로그 설계 (우리 코드가 보내는 이벤트 목록, 받는 곳: Amplitude)

### 원칙
- 이벤트 이름은 영어 소문자와 밑줄로 씁니다. 가안에 있던 engaged_60s는 같은 이름과 기준을 그대로 씁니다.
- 실험 분석에 쓰는 것만 계측합니다.
- 모든 이벤트에 UTM 다섯 값(source, medium, campaign, term, content)을 이벤트 속성으로 붙입니다. Amplitude의 자동 유입 속성은 첫 방문 기준이라 두 번째 방문부터 섞일 수 있어서 이벤트마다 직접 붙입니다.
- 개인정보는 보내지 않습니다. 이메일과 자유 입력을 받지 않고 설문은 선택지 코드만 보냅니다.
- 로그인이 없으므로 사용자는 Amplitude 기기 ID로만 구분합니다.
- Amplitude 자동 수집: 페이지 조회는 끕니다(landing_view와 겹침). 세션과 유입 경로는 켭니다. 검색 유입은 유입 경로로만 구분되기 때문입니다.

### 이벤트와 속성 정의: 택소노미 문서로 옮김 (2026-09-30)

이벤트 6개와 공통 속성 9개의 이름, 값, 분석 용도는 저장소의 택소노미 문서가 기준입니다. 이 문서에는 더 이상 이벤트 표를 두지 않습니다. 코드를 바꾸는 PR에서 표도 같이 고치고, 나중에 코드와 표가 다르면 자동으로 걸러내기 위해서입니다.
- 이벤트와 속성 표: [events.csv](taxonomy/events.csv)
- 이름 규칙, 이벤트 흐름, 설계 판단, 변경 절차: [택소노미 README](taxonomy/README.md)

요약: 핵심 전환은 interest_click. 모든 이벤트에 utm 다섯 값, round, variant, landing_page가 붙고 테스트 방문에만 is_test=true가 붙습니다.

**테스트 규칙 (결정 2026-09-30)**
- 두 사람이 페이지를 확인할 때는 항상 주소 끝에 `&debug=1`을 붙여 들어갑니다. 모든 이벤트에 is_test=true가 붙고 화면 아래에 이벤트 기록이 보입니다.
- debug=1일 때는 "설문 이미 봤다" 표시를 무시해서 들어올 때마다 설문이 뜹니다.
- 분석할 때는 Amplitude에서 is_test가 true인 이벤트를 제외합니다.
- debug 없이 광고 링크 그대로 눌러 본 기록은 걸러지지 않습니다. 그런 경우 날짜와 시간을 적어 두고 나중에 뺍니다.

UTM이 없는 방문(직접 접속, 검색, 공유)은 값을 `(none)`으로 보내 광고 유입과 구분합니다.

landing_page를 따로 두는 이유: 2차에는 랜딩이 두 개라서 링크를 공유받아 UTM 없이 들어오거나 링크를 잘못 넣어도 어느 페이지였는지 알 수 있어야 합니다. variant와 landing_page가 다르면 링크 오류로 보고 점검합니다.

### 메타 픽셀
- PageView만 보냅니다. 관심 버튼 맞춤 이벤트(InterestClick)는 보내지 않기로 했습니다(결정 2026-09-30). Amplitude에 같은 데이터가 있고, 메타 최적화에 쓰기엔 수가 적으며, 최적화를 켜면 A/B 노출 조건이 달라지기 때문입니다. 자세한 이유는 택소노미 README 7절.
- 픽셀은 광고 최적화용이고 분석은 Amplitude로 합니다.

### 주요 지표 계산 (Amplitude에서 볼 것)

| 지표 | 계산 | 나누는 기준 |
|---|---|---|
| 관심 버튼 클릭률 | interest_click 한 기기 ÷ landing_view 기기 | variant, round |
| 60초 체류율 | engaged_60s 기기 ÷ landing_view 기기 | variant, round |
| 설문 응답률 | survey_answer 한 기기 ÷ survey_view 기기 | variant, round |
| 유입 이유 분포 (Q1) | survey_answer(q1) answer별 비율 | variant, round (1차와 2차 합치지 않음) |
| 가장 먼저 보는 것 분포 (Q2) | survey_answer(q2) answer별 비율 | variant (1차와 2차 합침) |
| 성분표 확인 습관 분포 (Q3) | survey_answer(q3) answer별 비율 | variant (1차와 2차 합침) |
| 문항별 이탈 | survey_close의 step별 건수 | 없음 |

클릭률과 클릭당 비용은 메타 광고 관리자 숫자를 씁니다. Amplitude는 도착한 뒤의 행동만 봅니다.

## 2. UTM 값 규칙
- 전부 영어 소문자와 밑줄만 씁니다. 한글과 띄어쓰기는 링크가 깨지거나 같은 값이 둘로 갈라질 수 있어 쓰지 않습니다.
- 한 번 쓴 값은 실험 중에 바꾸지 않습니다.

### 광고

2026-10-02부터 광고 관리자의 이름과 UTM을 같은 글자로 씁니다(강사님 피드백). 이름만 보고 누구에게 무엇을 시험하는지 알 수 있게 하고, 다른 값이 생길 수 있는 것만 이름에 넣습니다. 낱말 뜻은 저장소 ads/README.md에 있습니다.

| 파라미터 | 무엇과 같은가 | 규칙 | 1차 값 |
|---|---|---|---|
| utm_source | | 고정 | facebook |
| utm_medium | | 고정 | cpc |
| utm_campaign | 캠페인 이름 | 제품_목표_실험_차수_시작일 | pdrncream_traffic_imgtest_r1_261002 |
| utm_term | 광고 세트 이름 | 겨냥_연령_성별_고르는방법_값 | ua_2040_female_interest_skincare |
| utm_content | 광고 이름 | img_그림_text_글_차수_버전 | 아래 표 |

| 차수 | A | B |
|---|---|---|
| 1차 (그림만 다름) | img_ingredient_text_common_r1_v1 (원료를 떠올리는 그림) | img_texture_text_common_r1_v1 (사용감을 떠올리는 그림) |
| 2차 (글만 다름) | img_(고른 그림)_text_ingredient_r2_v1 ("PDRN 연어크림") | img_(고른 그림)_text_review_r2_v1 ("바르면 쫀쫀해지고 광이 나는 크림", 2026-10-01 확정) |

- 시작일은 실제 게시일(YYMMDD)입니다. 게시가 미뤄지면 캠페인 이름과 링크의 utm_campaign을 같이 바꿉니다.
- 2차의 "(고른 그림)" 자리에는 1차에서 이긴 쪽에 따라 ingredient 또는 texture가 들어갑니다. 2차 캠페인 이름은 pdrncream_traffic_texttest_r2_(시작일)입니다.
- 코드는 utm_content에서 차수(round)와 소재 구분(variant)을 뽑습니다. variant는 A와 B가 다른 쪽의 값입니다(1차는 그림 값, 2차는 글 값). 규칙에 맞지 않는 값이면 둘 다 (none)이 됩니다. 값은 60자까지만 저장됩니다.
- 랜딩 첫 화면 사진은 utm_content의 그림 값으로 고릅니다. 2차 광고도 고른 그림이 그대로 나옵니다.
- 2026-10-01까지 쓰던 값: utm_campaign kr_2040_skincare, utm_content r1_name, r1_review. 게시 전에 바꿔서 이 값으로 쌓인 것은 테스트뿐입니다.

완성 링크 예시
```
https://seongbun-dotbogi.vercel.app/concept?utm_source=facebook&utm_medium=cpc&utm_campaign=pdrncream_traffic_imgtest_r1_261002&utm_term=ua_2040_female_interest_skincare&utm_content=img_ingredient_text_common_r1_v1
```

위 주소는 1차 공통 랜딩 기준입니다. 2차 소재별 랜딩 주소는 랜딩 디자인 확정 때 정하고 영어 소문자와 하이픈만 씁니다(SEO 1편 주소 규칙).

광고 링크는 손으로 넣습니다. 메타 동적 값(`{{ad.name}}`)은 광고 이름을 잘못 지으면 값이 틀어지고 소재가 4개뿐이라 쓰지 않습니다.

### 무료 SNS

| 채널 | utm_source | utm_medium | utm_campaign | utm_content |
|---|---|---|---|---|
| 스레드 | threads | social | organic | 글 번호 (t01, t02 ...) |
| 네이버 블로그 | naver_blog | social | organic | 글 번호 (b01, b02 ...) |

- utm_medium을 social로 두어 광고(cpc)와 한 번에 나눠 볼 수 있게 합니다.
- utm_term은 붙이지 않습니다. (none)으로 기록됩니다.
- 검색 결과(SEO)로 들어오는 방문에는 UTM을 붙일 수 없습니다. Amplitude의 유입 경로(referrer)로 구분합니다.

### 코드에서 바꿀 것
- 가안은 utm_content만 읽어 `frame`이라는 이름으로 붙였습니다. 새 랜딩은 UTM 값을 모두 읽고 round, variant, landing_page를 붙입니다.

## 3. 설문 문항

### 목적
클릭과 행동 데이터는 "무엇을 했는지"만 보여줍니다. 설문은 "왜 눌렀는지"를 묻습니다. 이 실험은 성분 언어(A)와 리뷰 언어(B) 중 어느 쪽이 반응을 끄는지 봅니다. 설문에서는 소재별로 응답 분포가 다른지를 봅니다.

### 띄우는 방식
- 화면을 가리는 팝업이 아니라 페이지 안에 붙는 작은 카드로 띄웁니다. 이탈을 늘리지 않기 위해서입니다.
- 관심 버튼을 눌렀을 때("출시 전 콘셉트 테스트였습니다" 안내와 함께), 또는 페이지에 들어온 지 20초가 지났을 때 중 먼저 오는 쪽에 뜹니다. 한 기기에 한 번만 띄웁니다.
- 카드 하나에 한 문항씩 보여 주고 위에 진행 표시(1/3, 2/3, 3/3)를 둡니다. 답하면 같은 카드 안에서 다음 문항으로 넘어갑니다. 중간에 그만둬도 앞 문항 응답은 남습니다.
- 순서는 Q1 → Q2 → Q3으로 고정합니다. Q3(성분표 확인)을 먼저 물으면 "성분"이 머리에 남아 Q2에서 성분을 고르는 쪽으로 쏠리기 때문입니다.
- Q1은 utm_medium=cpc(광고 유입)일 때만 띄웁니다. SNS나 검색으로 온 사람에게는 Q2와 Q3만 띄우고 진행 표시는 1/2, 2/2입니다.
- 한 번 뜬 카드는 끝까지 답하거나 닫을 때까지 남아 있습니다. 세 문항 모두 선택형이고 자유 입력은 받지 않습니다.
- 20초는 근거 데이터가 없는 절충값입니다. 1차 뒤 응답률을 보고 2차 전에 다시 봅니다.

### Q1. 광고를 누른 이유에 가장 가까운 것은? (하나 선택)

| 코드 | 선택지 |
|---|---|
| ingredient | 광고에 나온 성분이나 원료가 궁금해서 |
| texture | 광고에 나온 사용감(바르는 느낌)이 궁금해서 |
| effect | 광고에 나온 피부 효과가 궁금해서 |
| image | 이미지가 눈에 띄어서 |
| other | 기타 또는 잘 모르겠음 |

- 앞의 네 선택지는 방문자마다 순서를 섞습니다. 첫 번째 선택지가 더 많이 선택되는 쏠림을 줄이려는 것입니다. 기타는 항상 마지막입니다.
- 선택지에 "PDRN"을 직접 쓰지 않는 것은 B 소재로 들어온 사람에게 성분 이름을 알려 주지 않기 위해서입니다. 성분 쪽을 보고 눌렀는지 사용감 쪽을 보고 눌렀는지를 가릅니다. texture는 B를 리뷰 언어로 바꾸면서 추가했습니다(2026-09-30). effect는 광고에 없는 효과를 기대하고 눌렀는지 보려고 남겨 둡니다.
- **Q1은 A와 B 중 어느 쪽이 반응을 끄는지 가리는 용도가 아닙니다.** A에만 성분 이름이 있으니 A에서 ingredient가, B에서 texture가 많이 나오는 것은 당연합니다. Q1은 소재가 의도대로 읽혔는지 확인하는 용도이고 어느 쪽이 반응을 끄는지는 메타 CTR(보조로 관심 버튼 클릭률)로 봅니다.

### Q2. 화장품을 고를 때 가장 먼저 보는 것은? (하나 선택)

| 코드 | 선택지 |
|---|---|
| ingredient | 성분 |
| effect | 효능과 효과 |
| review | 리뷰와 평점 |
| price | 가격과 혜택 |
| brand | 브랜드 |
| other | 기타 |

- 응답자가 스스로 꼽는 기준을 직접 묻는 문항입니다. 성분(ingredient)과 리뷰(review)가 다른 기준보다 앞서는지를 봅니다.
- 앞의 다섯 선택지는 방문자마다 순서를 섞고 기타는 항상 마지막입니다.
- 소재와 무관한 질문이라 1차와 2차를 합쳐 봅니다.
- 참고 비교: CJ메조미디어 2025 설문(19~49세 여성)에서 뷰티 정보 검색 유형은 사용 후기 68%, 성분·원료 25%였습니다. 다만 그 설문은 복수 응답이고 질문도 "정보 검색 유형"이라 우리 문항(하나 선택, 가장 먼저 보는 것)과 숫자를 직접 비교하지 않고 방향만 나란히 둡니다.

### Q3. 평소 화장품을 고를 때 성분표를 확인하나요? (하나 선택)

| 코드 | 선택지 |
|---|---|
| always | 거의 항상 확인한다 |
| sometimes | 가끔 확인한다 |
| rarely | 거의 확인하지 않는다 |

- 성분 관여도로 응답자를 나누는 용도입니다. 예를 들어 "성분표를 자주 보는 사람일수록 A 소재에서 Q1 ingredient를 더 많이 골랐다"처럼 볼 수 있습니다.
- Q2가 "어느 기준이 먼저인가"라면 Q3는 "성분표를 실제로 얼마나 보는가"입니다. 두 답이 어긋나는 사람(예: 성분을 먼저 본다면서 성분표는 거의 안 봄)도 관찰 거리입니다.

### 해석 규칙 (미리 정함)
- 응답자는 클릭한 사람 중 답한 사람뿐이라 관찰로만 씁니다. 인과로 쓰지 않습니다.
- 비율은 항상 분모와 함께 씁니다. 예: "10명 중 3명(30%)". 응답이 적으면 한 명만 더 답해도 비율이 크게 움직이므로 A와 B의 비율 차이를 "차이가 있다"로 해석하지 않고 관찰로만 적습니다.
- 응답 수 예상: 소재당 7일에 10~40건 범위입니다. 파트너 추정(CTR 1% 가정, 약 10건)과 워밍업 실측(랜딩 도착 ÷ 노출 약 2.3%)이 크게 달라 1차 뒤 실측으로 다시 적습니다.
- 1차와 2차 응답 합치기 (결정 2026-09-29): 소재와 무관한 Q2(가장 먼저 보는 것)와 Q3(성분표 확인 습관)는 합쳐서 봅니다. Q1(광고를 누른 이유)은 1차와 2차 소재가 다르므로 합치지 않고 차수별로만 봅니다.
- 한계: 1차 공통 랜딩은 제품 이름 없이 만들어 B 유입자가 설문 전에 성분 이름을 보지 않게 합니다. 랜딩 어딘가에 성분 이름이 남으면 Q1 응답이 그쪽으로 기울 수 있다는 점을 결과 문서에 적습니다.
- 소재별 분포 차이는 "A 소재로 들어온 응답자 중 ingredient를 고른 비율이 N%, B 소재는 M%"처럼 대상, 숫자, 조건을 넣어 씁니다.

### 개인정보
- 선택지 코드만 보내므로 개인을 알아볼 정보는 없습니다.
- 처리방침에 "설문 응답(선택지)"을 수집 항목으로 추가합니다. GA4 삭제와 Amplitude 추가도 함께 고칩니다.

## 내일 강사님께 확인할 것

**여쭤볼 것**
1. 메타에서 A와 B를 어떻게 나눠 내보낼지. 같은 광고 세트에 넣으면 메타가 한쪽으로 노출을 몰고, 광고 세트를 나누면 보는 사람이 달라져 타겟 차이가 섞입니다. 광고관리자 A/B 테스트 기능(사람을 겹치지 않게 무작위로 나눔)을 쓰려는데 맞는지
2. 가상 제품형 랜딩(출시 전 콘셉트 + 관심 버튼 + 판매하지 않는다는 고지)이 메타 심사에서 문제가 없는지
3. 이벤트마다 UTM을 속성으로 직접 붙이는 방식이 괜찮은지
4. 설문 응답을 Amplitude 이벤트로 받는 게 맞는지, 별도 도구(구글 폼 등)가 나은지
5. 광고 클릭 수(메타)와 landing_view 수가 얼마나 차이 나면 정상인지
